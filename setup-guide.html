Setup & Approval Flow

Everything you need to get SysPro running on XAMPP and understand exactly how a form moves from Draft → Submitted → Approved → Completed through the two-pipeline approval system.

01 Requirements

Before starting, make sure you have the following installed.

XAMPP
PHP 8.1+, Apache, MySQL — the full local stack. Download from apachefriends.org.
Composer
PHP dependency manager. Download from getcomposer.org and install globally.
phpMyAdmin
Bundled with XAMPP. Used to import the database schema.
A modern browser
Chrome, Edge, or Firefox. Safari works but HTTPS self-cert warnings may appear.

02 Folder Setup

Extract the zip and place the project folder inside htdocs.

Windows path
C:\xampp\htdocs\processing-system-updated\

The project should be accessible at:

URL
https://localhost/processing-system-updated/public
-- or HTTP if you haven't set up SSL yet:
http://localhost/processing-system-updated/public
⚠ The folder name in htdocs must match the APP_URL path you set in .env. If you rename the folder, update the URL accordingly.

03 Environment File

Open .env in the project root (not inside public/) and fill in your settings.

.env
# ── App ──────────────────────────────────────
APP_NAME=ProcessingSystem
APP_ENV=local
# For HTTP (no SSL): uncomment the line below
# APP_URL=http://localhost/processing-system-updated/public
APP_URL=https://localhost/processing-system-updated/public
APP_TIMEZONE=Asia/Manila

# ── Database ─────────────────────────────────
DB_HOST=127.0.0.1
DB_PORT=3306
DB_DATABASE=psdb
DB_USERNAME=root

# ── Mail (Gmail SMTP) ─────────────────────────
MAIL_HOST=smtp.gmail.com
MAIL_PORT=587
MAIL_USERNAME=your@gmail.com
MAIL_PASSWORD=your-app-password   # Gmail App Password, not your login
MAIL_ENCRYPTION=tls
MAIL_FROM_ADDRESS=your@gmail.com
MAIL_FROM_NAME="Processing System"

Getting a Gmail App Password

1
Enable 2-Step Verification
Go to myaccount.google.com → Security and turn on 2-Step Verification. Required before App Passwords are available.
2
Create an App Password
Search for "App passwords" in your Google account settings. Set app to "Mail", device to "Other", name it "SysPro". Copy the 16-character password.
3
Paste into .env
Set MAIL_PASSWORD to the 16-character app password (no spaces). You can leave mail blank for local testing — forms will still work, notifications just won't send emails.

04 Database Setup

1
Start XAMPP
Open XAMPP Control Panel and start both Apache and MySQL.
2
Open phpMyAdmin
Go to http://localhost/phpmyadmin. Click New in the left sidebar and create a database named psdb with collation utf8mb4_unicode_ci.
3
Import the schema
Select the psdb database → click Import tab → choose config/psdb.sql from the project folder → click Go. This creates all tables and seeds 6 test accounts.
4
Verify tables exist
Click the psdb database in phpMyAdmin. You should see: roles, employees, forms, approvals, audit_logs, password_reset_tokens.
ℹ The SQL file also runs DROP TABLE IF EXISTS at the top, so you can safely re-import it to reset the database to a clean seed state during testing.

Add the notifications table (new in this version)

The updated project adds in-app notifications. Run this SQL in phpMyAdmin after the main import:

phpMyAdmin → SQL tab
CREATE TABLE IF NOT EXISTS notifications (
    id       BIGINT AUTO_INCREMENT PRIMARY KEY,
    user_id  INT NOT NULL,
    form_id  BIGINT NULL,
    type     ENUM('info','success','warning','danger') DEFAULT 'info',
    message  TEXT NOT NULL,
    link     VARCHAR(255) NULL,
    is_read  TINYINT(1) DEFAULT 0,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (user_id) REFERENCES employees(id) ON DELETE CASCADE,
    FOREIGN KEY (form_id) REFERENCES forms(id)     ON DELETE SET NULL
);
CREATE INDEX idx_notif_user ON notifications(user_id, is_read);

05 Install Dependencies

Open a terminal, cd into the project folder, and run Composer.

Terminal / Command Prompt
# Navigate to the project
cd C:\xampp\htdocs\processing-system-updated

# Install PHP dependencies
composer install

# If composer.json doesn't exist yet:
composer init --name="sme/processing-system" --type=project --no-interaction
composer require vlucas/phpdotenv phpmailer/phpmailer

After this, a vendor/ folder appears. That folder is already .gitignore-d — don't commit it.

⚠ If you get a session.cookie_secure error on HTTP, open config/app.php and comment out ini_set('session.cookie_secure', 1); for local HTTP-only development. Re-enable it before going live.

07 Roles Explained

1 Admin
Sees everything. Can approve or reject any form at any stage. Has the employee management screen. Bypasses all approver-assignment checks.
2 Approver
Immediate Supervisor. Assigned to Sequence 2 (Checker Approval) in both pipelines. Also sees any forms they submitted themselves.
3 Staff
Can create forms and submit them. Cannot see other employees' forms. No approval actions available. My Submissions page shows their own requests.
4 Dept Head
Admin pipeline: Review Approval (seq 3). Finance pipeline: Evaluation Approval (seq 4). Sees approval inbox for their assigned steps.
5 Checker
Finance pipeline only: Process Approval (seq 3). Not used in the admin pipeline. Approval inbox only shows finance forms at their stage.
6 Final Approver
Grant Approval (last sign-off) and Complete in both pipelines. The form is finished only after this role clicks "Mark as Completed".

10 Full Approval Walkthrough

Follow these steps using the six test accounts to see a complete approval cycle end-to-end. Use an Advance Payment (Finance pipeline) or a Leave Application (Admin pipeline).

1
Log in as Staff (Role 3)
staff@3ehitech.com / yourpassword
Go to the sidebar → pick a form type (e.g. Advance Payment) → click New Request. Fill in the fields. Click Save Draft. You will land on the form detail page showing status "Draft".
2
Submit the form
On the form detail page you will see the Your Action card at the bottom right. Click "Submit for Approval". Status changes to "Submitted" and the stepper highlights step 2. The system automatically finds the Role 2 approver (Approver account) and creates a pending approval row assigned to them.
3
Log in as Approver (Role 2) — Checker Approval
approver@3ehitech.com / yourpassword
The sidebar badge shows 1 pending. Go to Approval Inbox. Click View on the form. The Your Action card shows "Approve — Checker Approval". Optionally add remarks or attach a file, then click the green button. Status becomes "With Checker" → moves to "checker_approved".
4
Log in as Checker (Role 5) — Process Approval (Finance only)
checker@3ehitech.com / yourpassword
Approval Inbox shows the form. Click "Approve — Process Approval". Status → "process_approved". Skip this step for admin-pipeline forms — it goes straight to Dept Head.
5
Log in as Dept Head (Role 4) — Evaluation / Review Approval
depthead@3ehitech.com / yourpassword
Finance: button says "Approve — Evaluation Approval". Status → "finance_reviewed".
Admin: button says "Approve — Review Approval". Status → "department_reviewed".
6
Log in as Final Approver (Role 6) — Grant + Complete
final@3ehitech.com / yourpassword
Click "Grant Approval Request" → status becomes "final_approved". The action card refreshes. Click "Mark as Completed" → status becomes "completed". The stepper shows all steps as done ✓. The Staff account receives an in-app notification.
✓
Log back in as Staff — verify
Go to My Submissions. The form shows status "Completed" with a green badge. The notification bell in the topbar shows the completion message. The form detail stepper shows all nodes checked with the approver name and date at each step.

To test a rejection

At any approval step, fill in a Remarks reason and click the red Reject button instead. All remaining pending steps are marked rejected, the form status becomes "Rejected", and the submitter gets a notification with your remarks. The stepper shows the completed steps as done and the rest as rejected.

11 Common Issues

"No active approver found for role ID…" on form save

The system tried to seed approval rows but found no active employee for that role. Check employees.is_active = 1 for the relevant role in phpMyAdmin. This happens if you deleted a seeded account.

Blank page or 500 error

Enable PHP error display temporarily: add ini_set('display_errors', 1); at the top of public/index.php. Most likely causes: vendor/ folder missing (run composer install), wrong DB credentials in .env, or the notifications table not yet created.

"You are not the assigned approver" error

You are logged in as a user with the correct role but not the one specifically assigned in the approvals table. The system assigns the least-loaded user per role at form creation. Check the approvals table to see which approver_id was assigned for that sequence, and log in as that employee.

CSRF token mismatch

Usually caused by opening the same form in two tabs and submitting the older one. Reload the page and retry.

session.cookie_secure warning on HTTP

config/app.php — comment this out for HTTP-only local dev
// ini_set('session.cookie_secure', 1);

12 Changing Passwords

Three ways to change an account password:

Option A — via the app (Forgot Password)

On the login page, click Forgot Password. Requires MAIL_* settings configured in .env so the reset link can be emailed.

Option B — phpMyAdmin (quickest for dev)

Step 1 — generate the hash
"C:\xampp\php\php.exe" -r "echo password_hash('newpassword', PASSWORD_BCRYPT, ['cost' => 12]);"
Step 2 — update the DB
UPDATE employees
SET    password_hash = '$2y$12$...'
WHERE  email = 'staff@3ehitech.com';

Option C — adding a new employee

phpMyAdmin → SQL
INSERT INTO employees
    (employee_code, full_name, email, password_hash, role_id, department)
VALUES
    ('EMP-0007', 'Maria Santos', 'maria@company.com',
     '$2y$12$...(hash)...',
     3,     -- role: 3 = Staff
     'Finance');
✓ New employees are automatically available to be assigned as approvers if their role_id matches a pipeline step and is_active = 1. The system picks the least-loaded approver per role at form creation time.
